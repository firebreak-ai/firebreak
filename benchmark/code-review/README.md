# Code-Review Detection Benchmark

Measures how well Firebreak's code-review pipeline finds real defects, scored against
the [Martian Code Review Benchmark](https://github.com/withmartian/code-review-benchmark):
**50 pull requests across five public repositories** (cal.com, Discourse, Grafana,
Keycloak, Sentry — ten PRs each), each with a human-curated set of "golden" findings.

Firebreak reviews each PR, an LLM judge matches its findings against the goldens, and
the run reports precision, recall, and F1. Results are archived per release under
[`results/`](results/) so successive runs show the delta.

## How a run works

The harness is a pipeline of small, single-purpose tools. Each resolves its siblings
relative to its own location, so the directory is self-contained.

| Step | Tool | What it does |
|------|------|--------------|
| 1. Dataset | `manifest.json` | The 50-PR dataset: repo, PR number, base/head SHAs, golden findings. |
| 2. Enrich | `fetch_pr_shas.py` | Fills in each PR's base/head SHA via the GitHub API (`gh`). |
| 3. Check out | `clone_repos.py` | Builds a per-PR git worktree at the base commit with the PR diff applied (shared blobless caches). |
| 4. Review | `run_reviews.sh` | Runs Firebreak's code review on each PR via Claude Code headless mode. Two modes: **full-repo** (reviewer browses the whole repo at PR HEAD, matching how the benchmark's peer tools review) and **diff-only** (reviewer sees just the diff). |
| 5. Normalize | `inject_results.py` | Converts Firebreak's findings into the judge's input schema. |
| 6. Judge | `judge_anthropic.py` | Three independent Sonnet judges match findings against the goldens (true positive / false positive / false negative). |
| 7. Aggregate | `judge_consensus.py`, `aggregate_consensus.py`, `aggregate_judge.py`, `aggregate_tokens.py` | Combines the three judge runs into a consensus verdict and computes precision / recall / F1 and token cost. |

`extract_candidates.py` pulls candidate findings out of raw review transcripts;
`benchmark-prompt-fullrepo.md` and `benchmark-prompt-diff.md` are the review-mode
prompt overrides.

Run `./run_reviews.sh --help` for flags (model, repo filter, review mode, full
pipeline).

## What's tracked here

Tracked: the harness (scripts, prompts, dataset) and, per release under `results/`,
the written reports plus the full scoring chain behind them (judge input → three judge
runs → consensus) so every reported number is auditable.

Not tracked (regenerated by the harness, kept out of the repo): cloned repos and
worktrees, generated diffs, raw review transcripts, run logs. See `.gitignore`.

## Reproducing or extending a run

You need the `gh` CLI (authenticated), Claude Code, and `uv`. Point `--tool-name` at
the release you're measuring, run the full pipeline, then archive the reports and
scoring JSONs under a new `results/<release>/` folder. See [`results/`](results/) for
the layout and the existing 0.4.0 baseline.
