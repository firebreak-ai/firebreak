# Changelog

## [0.5.2]

### Added
- **One review shape across every review type.** Code review, test review, fresh-eyes, quality scan, doc reconciliation, and two new review types (coherence review and task review) now all run on a single shared spine: a *researcher* pass that reads the work cold and surfaces candidate findings, then a *challenger* pass that independently verifies or rejects each one. What used to be a handful of bespoke per-domain reviewer agents collapses into two general-purpose role agents (a researcher and a challenger) plus a small *lens* document per review type that supplies the criteria — the knowledge that makes a code review a code review, or a test review a test review, lives in the lens, not in a separate agent. Behind the prose, an executable pipeline reshapes findings deterministically the same way for every type: strip the author's framing so the challenger judges the work and not the pitch, validate each finding against its lens, filter by type and severity, drop challenger-rejected findings, and re-attach verdicts — built as small composable commands a skill chains together rather than inline shell that drifted between reviews. Two new review types ship on this spine: a coherence review that checks a task breakdown's cross-task contracts line up, run behind a new coherence gate, and a task review that replaces the old standalone test-reviewer at the breakdown stage. The spec gate gains a matching backstop: an independent test-plan review must be written and accepted before a spec passes, and spec review plus the cold fresh-eyes read now actively hunt residual ambiguity — any name, shape, contract, or observable behavior still vague at completion fails the spec. Glossary entries added for the review pattern, researcher, challenger, lens, preset, and the composable-pipe / neutral-handoff plumbing. Full overview in `docs/architecture-overview.md`.
- **Cross-model second opinion.** A new `/fbk-cross-model-review` skill sends a document or code change to a *different* model (Codex / GPT-5.5) for an independent read, reusing the same review lenses for criteria. It is strictly opt-in — off unless a project turns it on in config, with an explicit note that the target content leaves the machine to a third-party model — and its results are always *candidate* findings to triage, never verified findings. Underneath sits a hardened runner that never crashes the caller: it always prints a status/report-path/cause object and exits cleanly whether the external model succeeds, returns nothing, times out, or needs a login, writes its report atomically, validates the reasoning-effort value against config-injection, and inlines the target content into the prompt so the external model's read-only sandbox can actually see it. This pipeline was used on itself — repeated cross-model reviews of its own implementation caught a layer of real defects that hundreds of passing tests and same-model review missed.
- **Observability substrate — a durable, attributed, queryable record of what actually happened in a workflow run.** At workflow close the new harvest engine joins three machine-written sources — the harness event stream, the Claude Code workflow journal (the agent roster), and the per-agent transcripts — into one per-run record under `.fbk-capture/runs/<run-id>.json`, with no operator command. Each unit carries its kind of work (a closed five-member *shape* vocabulary — distill, implement, review, synthesize, gate — resolved from the agent persona, never invented), how it was organized (*topology*: cardinality and stance), which persona was loaded (*asset bundle*), and involuntary signals the harness records below the agent: duration, per-transcript token sums, and gate outcome. A new reader, `fbk.py run-retro <run-id>`, prints a per-unit table assembled purely from the record — deterministic, byte-identical across reads, never narrated by an agent; null fields render as an em dash, a crashed run shows a partial-record warning, a missing record an explicit no-record line. Finalization fires from already-wired hooks: `PostToolUse(Workflow)` finalizes the just-closed run, `SessionStart` sweeps the newest closed-unfinalized run for crash recovery — scoped to the current project so a shared global install never finalizes another project's runs. The record honors the project's capture level exactly as the event stream does (at `off` no record is written at all; otherwise free-text is passed through `schema.redact()` at the resolved level), is written through the confined, atomic capture path, and is portable (survives a project move). A purpose-built three-agent conformance workflow proves the spine end to end. This is the thin first slice: the rich asset-bundle fields (instructions, decision-tree) are structurally reserved but populated only once a dynamic assembler can stamp them truthfully, and cross-run/self-improvement/failure-attribution readers are deferred. Full overview in `docs/architecture-overview.md`.

### Changed
- **Pipeline-wide hardening from the realmind2 rewrite retrospectives.** A full `/fbk-improve` cycle over three new capability retrospectives plus a rewrite-vs-original comparison study landed ~60 targeted instruction changes across the breakdown, review, design, spec, intent, and implementation chains. The through-line: convert what reviews kept catching late into what earlier phases prevent or verify mechanically. Highlights — compile legality gets a verification layer (a breakdown-time compile-coherence checklist, a whole-wave compile pass in the task-review lens, and a redeclaration check in the coherence lens, after compile-breaking task-file defects walked past four reading instruments in two separate walks); expected test values are derived by executing shipped code or showing the arithmetic, never by mental simulation (hand-derived assertions survived every review round while qualitative ones failed correct code); cross-model review becomes a standing instrument (a standard closing step at code review and the preferred post-fix verification pass, scoped to the fix set at ~1/5 cost — in both completed walks it caught every real code-review defect the internal loop missed); reviewer agents harden against known failure modes (absence claims require opening the path, author-asserted intent is a claim to verify, verdict tallies are computed rather than written, phase-framing lives in the lenses permanently); and numeric-config designs now audit every consumer seam for a config path and validate degenerate values (zero/non-finite) that silently disable ratified behavior. Implementation teammates now spawn with the `fbk-implementer` persona (shipped in 0.4.0 but never wired) and use git worktrees for scratch verification.
- **Canonical names replace bare stage numbers across the live SDL.** Installed SDL assets now refer to work by phase name, gate name (matching the `fbk.py` command map), and retrospective section name (matching the headers the retrospective writer emits), retiring "Stage N" identifiers. This removes a whole class of drift where one file's stage number fell out of sync with another's after the pipeline grew from four phases to seven. Scope is live assets only.
- **Repo no longer tracks per-feature SDL working scratch.** The entire `ai-docs/` tree (specs, designs, reviews, retrospectives, task breakdowns each feature generates) is now ignored — the pipeline still writes it to the working tree, so gates and ceremonies are unchanged; the repo simply stops carrying single-use artifacts. The code-review benchmark, which is real CI-tested infrastructure that happened to live under `ai-docs/`, was relocated to `benchmark/`. A stale code-review report was removed from the repo root.

### Fixed
- **Contracts gate no longer swallows fields across lines.** The entry-field regex could span newlines, so a colon-less continuation bullet under one field (an `invariants:` list item) consumed the following `covers:` key and every entry reported "missing covers" — found live during the affect walk, where authors had to reorder fields to dodge it. The field-name match is now anchored to a single line.
- **Design-anchor check fails loudly on non-standard contract ids.** A design page numbering its contracts with a capability prefix (`IF-A-NN` instead of `IF-D-NN`) previously produced zero matches and the carry-verification check silently passed while verifying nothing; it now names the non-standard ids and fails.
- **The prerequisite probe actually runs.** The `precheck` script shipped since the capability-entry work but was never registered in the `fbk.py` dispatcher, so the documented invocation failed in every skill that named it; it is now a registered command, unknown phase labels are rejected loudly (title-case "Code Review" previously fell through to a silent `ready: true`), and every phase skill references the real, runnable command with a manual fallback.
- **Upgrading now removes files the new version no longer ships.** The installer recorded every file it wrote in `.firebreak-manifest.json` and read that record only at uninstall time — an upgrade copied the current files over the old ones and then replaced the manifest, erasing the only evidence that a dropped file was ever Firebreak's. Assets removed by a release therefore survived every future upgrade, and a stale copy of a deleted agent or skill stays live for the agent that loads it. An upgrade now reads the outgoing file list before replacing it, and once the current files are safely in place removes those the new version no longer ships, then drops any directory left empty. Only paths the previous install recorded are eligible, so files written by hand are never candidates; entries resolving outside the install target are refused rather than followed; a damaged previous manifest warns and skips the cleanup instead of failing the upgrade; and `--dry-run` reports each removal without making one. The install summary now reports files removed alongside files installed. This release is the first to delete assets — four reviewer agents — so without it every existing install would have kept them.

### Removed
- **Four per-domain reviewer agents** (the code-review detector and challenger, the test reviewer, and the fresh-eyes reviewer) deleted and consolidated into the two general-purpose researcher and challenger agents plus per-type lenses introduced by the unified review shape. Their registry entries were removed and every skill, doc, and test that referenced them repointed at the surviving agents.

## [0.5.1]

### Added
- **Intent and Design phases — the SDL is now a six-phase loop.** Work can start at intent (ground the change in project context, surface ambiguity through grilling and a cold fresh-eyes read before any spec is written) or at design (explore approaches, produce design pages and a manifest), then flow through spec → breakdown → code-review → implement. The operator enters at whichever phase fits the work — a small bugfix can still start at spec. New phase skills `/fbk-intent` and `/fbk-design` drive the two new phases, each with its own gate, backed by new architect, product-author, and fresh-eyes reviewer personas. Full overview in `docs/architecture-overview.md`.

- **Technique skills — a reusable capability layer between phases and agent personas.** Five skills any phase can call with a stable interface: `/fbk-grilling` (one-question-at-a-time ambiguity resolution, also available out-of-ceremony as `/grill-me`), `/fbk-fresh-eyes` (a context-clear subagent reads an artifact cold and returns severity-ranked observations), `/fbk-quality-scan` (top-five code-quality scan at review time), `/fbk-test-review` (validates AI-written tests for known failure modes — pre-lock at breakdown and a final pass at code review), and `/fbk-doc-reconcile` (reconciles shipped code against the durable docs).

- **Interface contracts gate.** The spec gate now checks that declared module seams — the contracts between components — are actually covered: a contracts page in design, a contracts section in spec, and elevation of any contract drift through the architecture reviewer's brief. Blast radius is derived with reference tooling rather than guessed.

- **Deterministic metrics plane — the pipeline measures itself from code.** A Claude-level hook router and a wrapper around the dispatcher's command chokepoint feed one `report` command that aggregates per-stage durations, gate first-pass rates, parks, rework, scope violations, code-review detection rounds, and token usage. The report runs ad-hoc and is auto-injected into the retrospective, replacing agent-narrated metrics. Capture is globally armed but records only in Firebreak-managed or explicitly-marked projects, always into a project-local gitignored directory; tool-call and prompt payloads are captured only at the `full` level (default is `standard`).

- **Drift advisory signal in the code-review gate.** The gate now reads the verdict inside the test-review artifact instead of only checking that it exists. A non-accepted verdict — the signature of a renamed-but-content-identical locked test — raises a non-blocking advisory finding for operator triage while the gate still passes. This formalizes one rule across all gates: block when the problem is agent-fixable (missing artifact, hash mismatch), advise when it needs human judgment.

- **Durable docs.** Three small, git-tracked, in-branch-maintained docs now outlive each feature: `GLOSSARY.md` (canonical terminology), `docs/decisions-log.md` (append-only record of constraining decisions), and `docs/architecture-overview.md` (living project overview). Cold-agent and new-hire onboarding starts here.

### Changed
- **All phase gates follow one hybrid pattern.** Each gate pairs a mechanical anchor (deterministic structure check — file presence, hash match, manifest bidirectionality) with a semantic anchor tied to a concrete artifact a technique skill produced, so judgment inspects something verifiable rather than re-running from scratch.
- **Per-task breakdown files are no longer tracked in git.** The single-use task scaffolding each feature generates is now ignored; specs, designs, reviews, retrospectives, and the task manifest stay tracked.

### Fixed
- **Installer writes a manifest on a fresh target.** Settings-merge and manifest-write previously ran before the target directory existed, silently leaving a fresh install with no settings and no manifest — and a manifest-less install can't be uninstalled. The target directory is now created up front.
- **Installer no longer ships dev cruft.** The prune set now also drops caches, build metadata, nested `.claude`, `.git`, and the dev-only test tree.
- **Uninstall no longer orphans `fbk-scripts/`.** Runtime-generated `__pycache__` bytecode — written the first time `fbk.py` runs — was absent from the manifest, so uninstall couldn't remove it and the empty-directory prune left the tree behind. Uninstall now clears those caches, the same fix class as the venv-orphan removal.
- **Breakdown gate reads the right heading.** The acceptance-criteria section match is anchored to a heading start, so a mid-line prose mention can no longer be mistaken for the section.
