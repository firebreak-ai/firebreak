Use when configuring the runtime or inspecting historical evidence. Ordinary continuation uses the current work view.

## Project settings and observability

`.fbk/config.json` opts the project into this workflow. Defaults are `schema_version: 1`, `reviewer_model: "opus"`, `review_timeout: 1200`, `reviewer_max_turns: 100`, `reviewer_effort: "medium"`, and `check_timeout: 300`. Optional `second_reader` is an executable argument array: it reads the prompt on stdin and returns the native summary/findings contract plus `context` with status, inspected_files, supporting_files, and missing_context. The context must be complete and include every required input; these claims are validated structurally and remain attributed model reports. Configure it deliberately; no external provider is called by default. `capture: false` disables the new hook event log.

`reviewer_max_turns` must be a positive integer. It is a safety ceiling on each native session, including each council session, the second reader's assessor, and each delegated investigation worker. Turns are not a budget: a turn count is a proxy for cost and a session that reads sources carefully uses many of them, so the default of 100 is high enough that only a genuinely looping session reaches it. Reaching the ceiling is an ordinary failed attempt. The round records the failure with its diagnostics (host output, exit code, reported turns, configured limits), and another attempt may run while phase review rounds remain. The review round limit is the repetition control. `review_timeout` bounds each subprocess in seconds (positive, at most 86400; default 1200). It is the same kind of safety net as the turn ceiling, this time against a hung or wandering session: a session that reaches it is stopped and the attempt is recorded as failed with its diagnostics (the configured limit, elapsed seconds, and whatever output was captured), and another attempt may run while phase rounds remain. The reviewer is told the limit in its prompt. Lower these only for testing, for example `"reviewer_max_turns": 24, "review_timeout": 600`. Separately, `review_round_timeout` (default 9999 seconds, independent of `review_timeout`) is the wall clock for one whole managed review round, covering every session and investigation in it; exhausting that clock pauses phase review for human help, and after human authorization `extend-review` with the operator's reason is the only way to continue. Budgets are never extended automatically.

`status` gives the current phase, stale inputs, ownership, and next action. `workflow-report` gives the current work view and capture health; `workflow-report <unit> --history` expands durable phase evidence, audit history, review rounds, and reported review usage. Hook and context-emission events live under `.fbk/runtime/`; they omit prompts and arguments and stop at a 10 MB cap. Capture health distinguishes disabled, not observed, recording, capped, degraded, and unknown. Recording means events were observed, not that coverage is complete. Write failures are disclosed when a health marker can be saved; inaccessible storage remains unknown. Authoring-session token usage is not claimed. Telemetry failure never grants or denies a crossing.

For required phase observations and retrospective evidence, read `retrospective.md`. For an improvement proposal or evaluation, read `improvement.md`. Pending phase observations appear in ordinary handoffs; the historical prose remains an explicit analysis input outside native acceptance-review snapshots.

Commit `.fbk/config.json`, unit documents, and `state.json` with the implementation. Keep `.fbk/runtime/` untracked. State checksums detect accidental corruption, not hostile tampering. A damaged record is restored from git; ordinary artifact changes go through reopen.

Hooks prevent covered Edit, Write, and NotebookEdit operations; Bash, external tools, disabled hooks, and hook timeouts are prevention gaps. Explicit close always revalidates artifact and test evidence. Firebreak is a cooperative development workflow, not a security boundary against an agent with arbitrary shell access. Use host permissions and sandboxing for that boundary.

Native review requires a Claude Code host supporting `--safe-mode` and `--restricted`. Firebreak retains ordinary Claude authentication, disables automatic host customization discovery, and confines native file tools to an original-source snapshot. An unsupported host fails with an actionable message. Optional external readers receive the snapshot as their working directory; their process access depends on their own host confinement.
