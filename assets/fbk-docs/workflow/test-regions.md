When the scope declares a test region for a file, the tests live at the end of that source file instead of in a file of their own. The region starts at the first line its start expression matches and runs to the end of the file; everything above it is production code. Write the tests inside the region and keep every test below its start line. Firebreak finds the region by matching text, never by reading the language, so a start line elsewhere in the file moves the region: keep any line the start expression matches out of the code above, since an edit adding one is refused as a change to the tests. The write hook also refuses edits to a region-bearing file with mixed line endings or a UTF-8 byte-order mark; convert it to one line ending with no byte-order mark first. As illustrations only, a Rust project might use `^#\[cfg\(test\)\]$` to find `#[cfg(test)]` before `mod tests`, and a C project `^#ifdef UNIT_TEST` to find an `#ifdef UNIT_TEST` block; the spec sets the actual expression. The test checkpoint locks the region, and the file must be in your task's `files` for you to change either part.
