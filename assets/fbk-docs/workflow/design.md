Shape the code so every promised behavior is observable through them, without reaching into internal parts. List the choices a design file makes in its `Design choices` section: one heading per choice, one level below the section heading, with a plain-language name. Inside each choice, link the commitments it serves with ordinary Markdown links to their heading anchors, the path relative to the design file: `[Fast restore](../prd.md#fast-restore)`. A child unit may also link its parent's commitments. Design close checks every choice and every commitment and names each failure: a choice with no commitment link, a link into `prd.md` that misses a commitment (a heading outside Commitments, a heading inside a commitment, a missing anchor, an anchor two headings share, or the whole document), and a commitment no choice links. A design file without the section contributes no choices. Write the section in the Markdown that `linked-sections.md` beside this file describes; Firebreak refuses anything else and names the file, the line and the item.

Run a bounded experiment when the choice depends on uncertain host behavior. Leave private implementation structure to implementation when it has no shared-contract consequence. Revisit settled architecture only with evidence that it cannot meet the requirements.

For each choice, state the rules it must keep everywhere it applies, such as "a saved record is replaced only after its replacement is safely written". When you list the places a rule applies, say whether the list is complete. An incomplete list is a set of examples, and the rule still governs.

Review consequential responsibility boundaries now: identify who owns each shared policy and whether a normal change requires synchronized edits across independent owners. Trace risks to accepted intent and concrete failure modes. Distinguish user-approved constraints from necessities of the design: approval of a stricter stored-data rule does not establish that looser handling would be unsafe. Resolve demonstrated coupling that makes the approach error-prone before acceptance; defer private helper and file layout choices without shared-contract consequences. Small cohesive modules and intentional test seams do not need extra layers merely to look architectural.
