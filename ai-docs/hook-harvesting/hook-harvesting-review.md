## Architectural soundness

**[blocking] Injection predicate fires on park, not just on completion.** The spec keys retrospective injection on "the previous state is one of the eight working stages" (the integration seam, contract IF-D-07, AC-18). But a working stage transitions to its checkpoint state on success *and* to `PARKED` on failure — in both cases the previous state is a working stage (verified in `state.py:113-131`: `prev_state = current` is the working stage whether `new_state` is `IMPLEMENTED` or `PARKED`). The predicate as written injects a "stage completed" metrics block on every park, when the stage actually failed — directly contradicting AC-18's own "must not fire when leaving toward PARKED." **Resolution**: the predicate must key on the *pair* — previous state is a working stage AND new state is not `PARKED` — and the call site must pass the local `prev_state`, not the persisted `current_state`. Fix the wording in the seam, IF-D-07, and AC-18. This traces into the design (`reporting-and-injection.md` made the same single-state claim) and should be corrected there too.

**[blocking] The installer does not exist where the spec targets it, and its merge engine cannot perform the assigned migration.** The spec names `install.sh` under `assets/fbk-scripts/` and assigns it three changes (register the router, gitignore `.fbk-capture/`, remove leftover project-level registrations). Verified: there is no such file. The real installer is `installer/install.sh`, delegating the settings merge to `installer/merge-settings.py`, which merges the template `assets/settings.json`. Two structural problems: (1) `merge_hooks` is **add-only** (canonicalize-and-append, no removal path) — the duplicate-registration removal (IF-S-03, AC-19) is net-new capability the spec never homes; (2) the router hook entries must be added to the `assets/settings.json` template, and the installer's `sed` transform rewrites `$HOME/.claude/` to `$CLAUDE_PROJECT_DIR/.claude/` on project installs, which would re-introduce the very project-vs-global divergence the migration eliminates. **Resolution**: correct the installer paths; name `merge-settings.py` and `assets/settings.json` as the real touch points; specify the removal as new logic with a defined home; reconcile the `sed` rewrite with the global-path requirement.

**[important] The router runs as a standalone process without `fbk.py`'s path bootstrap.** The router lives at `fbk/capture/hook_router.py` and imports `fbk.capture.*`, but it is fired by Claude's hook runtime by absolute path — not through `fbk.py`, which is where `sys.path` is set up (the script dir and venv site-packages, `fbk.py:8-17`). A bare `python3 .../hook_router.py` will not have `fbk` importable and its imports fail in production while passing in tests (where `fbk` is already on the path). **Resolution**: specify the router's own `sys.path` bootstrap (mirror `fbk.py`'s inserts), or keep the router flat at the install root with an explicit path insert. Name this in the contract so the port task produces something that runs as a bare hook process.

**[important] A third `audit.log_event` call site is unaccounted for.** The spec scopes audit retirement to two call sites (spec gate, task-reviewer gate). Verified: `fbk/hooks/dispatch_status.py:78` is a third live caller (and it passes a dict where `log_event` wants a JSON string — a latent pre-existing bug, out of scope). **Resolution**: enumerate all three sites and state explicitly that dispatch-status stays on `audit` (the decision: only the two gate sites migrate), so the breakdown does not have to rediscover it. *(Found independently by Architecture and Quality.)*

**[important] The chokepoint and the injector nest on the state command.** `fbk.py state transition` is itself dispatched, so a single transition runs through the chokepoint redirect *and* the in-function injector. This is fine today (the injector writes to a file, not stdout), but the spec treats the two seams as independent when they are nested — and if the pipeline ever calls `transition_state` in-process, the injector fires while the chokepoint does not. **Resolution**: state that `state transition` is both wrapped and injected (the two events are complementary, as already noted for `task-completed`), and that the injector must never write to stdout because it can run inside the redirect frame.

**[informational] The chokepoint wraps every command, including interactive ones.** The save-buffer-then-flush mechanism is justified by the gates' one-line JSON output, but the same wrapper wraps every `COMMAND_MAP` entry — including the council/ralph interactive paths that print incrementally across many calls. For those, all stdout is withheld until the command finishes. **Resolution**: confirm the chokepoint only buffers for gate/hook/state commands, or document that all dispatched stdout is now deferred-then-flushed.

**[informational] Latent import cycle between `report` and `retro_injector`.** `report.py` imports `fbk.capture.*` while `retro_injector` imports `report.stage_summary` (IF-D-07). It resolves only if the injector keeps that import function-local. **Resolution**: name the function-level-import constraint in the contract so a task author does not hoist it to module scope.

**Verified correct** (checked against source, no change needed): the stdout-and-exit seam mechanism is sound against all four real gates (print-final-JSON-then-`sys.exit`, diagnostics on stderr, no `with`/`atexit` reliance); `retro.append_section` is reused correctly and needs no change; `VALID_TRANSITIONS` has the shape the predicate reads (the defect is the predicate's logic, not its data source); the flat `report.py` + `fbk/capture/` split matches existing convention.

## Threat modeling

Full analysis, data flows, and STRIDE table in `hook-harvesting-threat-model.md`. The three blocking threats:

**[blocking] The capture gate keys on a shared directory name, so a hostile repo can force capture.** `project_is_instrumented` returns true on the bare presence of `.claude/automation/` — a shared Claude namespace, not Firebreak-private. A repo shipping a committed `.claude/automation/` plus a `.fbk-capture/capture.cfg` with `capture_level=full` turns capture to full the instant the operator opens it, recording prompts and tool arguments into a file inside the attacker's tree. **Resolution**: gate on a Firebreak-specific marker the installer writes (a sentinel under `.claude/automation/`), not the bare directory; never honor `capture_level=full` from a git-tracked config.

**[blocking] Router cwd provenance is unpinned; gate-dir and write-dir can diverge.** The prototype resolves the router's directory from the hook payload / `$CLAUDE_PROJECT_DIR`, and the spec never pins a single source. If the gate evaluates one directory and the write lands in another, prompts from an unrelated session can be written at full under attacker influence. **Resolution**: pin one cwd source; gate and write the same resolved path; state precedence explicitly; add an AC asserting gate-dir equals write-dir.

**[blocking] Symlinked capture dir/config escapes confinement.** Existence checks pass and the level read and the write both follow a symlink, so full-capture prompt text can land outside the project tree, escaping the gitignore confinement the model rests on. **Resolution**: realpath-confine `.fbk-capture/` under the project root; refuse a symlinked `capture.cfg`. State in IF-D-03/IF-D-05; add an AC.

**[important] Capture file can be committed before it is gitignored.** Capture begins when `capture.cfg` is present, which can precede the installer's gitignore step or occur in an explicit-marker project the installer never touched. In that window `events.jsonl` (prompt text at full) is committable; a hostile repo can also ship a `.gitignore` that fails to exclude it. **Resolution**: the writer self-creates `.fbk-capture/.gitignore` containing `*` on first write, independent of install order.

**[important] Baseline locks make the events file an unbounded-growth DoS primitive.** The pruner never drops locked-spec lines and the size cap is the only bound; locked lines exceeding the cap grow the file without limit (disk exhaustion), and `locked/` is writable by sandboxed agents. **Resolution**: cap total protected bytes; drop oldest locked lines past the ceiling with a report warning.

**[important] Standard-level payload stripping is per-producer, so one producer can leak.** Stripping is described across four producers; the verification hook's out-of-scope file paths and the code-review data are not clearly governed at standard. **Resolution**: centralize level-based redaction in the writer (or a shared `redact(data, level)`); add a drift-style test that no standard record carries a free-text payload field.

**[important] The code-review-rounds trust boundary needs type/range/size bounds.** Containment is correct (worst case is "no event," never a gate bypass — verified), but IF-D-06 bounds only field presence, not types or ranges, and the values feed the kill-rate math. **Resolution**: specify integer types, non-negative ranges, max rounds-list length, max file size; out-of-range treated as malformed.

**[informational]** Full-capture gate-result payloads may contain source snippets and scanner findings — document this in the full-capture operator note (the enforcement boundary itself is correct). Installer duplicate-removal must anchor its match to the exact old router command and be idempotent. The gate's `capture.cfg` read must be a bounded single-line read. Unencrypted-at-rest is an accepted residual risk (full is opt-in, gitignored, per-project) — recorded, not mitigated.

## Quality: testing strategy and impact

**[blocking] The "retired tests" do not exist, so the audit-to-event-writer swap ships untested.** The spec and the chokepoint-and-audit-retirement slice claim `test_gates_spec.py` and `test_gates_task_reviewer.py` "assert the two `audit.log_event` calls" and retire those assertions. Verified: neither file references `log_event` or `audit` anywhere; the only such test is `test_audit.py`, which correctly stays. So the retirement entries are no-ops and the call-site swap (in `spec.py` and `task_reviewer.py`) ships with **zero** coverage that the event-writer call replaced the audit call. **Resolution**: drop the "retired" framing; specify *new* integration assertions that each gate, on pass and on fail, writes a correctly-stamped envelope (run the gate, assert a line lands in the events file).

**[blocking] AC-02 (router writes to the project, never the global config dir) has no test.** This is the governing privacy/location guarantee, and a path-resolution bug writing to the global dir is exactly the leak the feature must prevent. The router tests cover gated write/no-write but never assert the write *destination*. The end-to-end negative test ("no entries anywhere") catches a write to *no* location, not a write to the *wrong* location. **Resolution**: add a router integration test asserting the events file is created under the project `cwd` and that no file appears under a fixture global-config path. *(Reinforces the Security cwd findings.)*

**[important] `append_section` duplicates the metrics block on rework.** `retro.py:append_section` is pure append with no de-dup. On rework (a stage completes, parks, re-enters, completes again) the injector fires twice and appends a second identical-heading metrics block. The spec's predicate test exercises the rework completion but asserts nothing about the duplicate outcome. **Resolution**: decide whether re-injection replaces or appends; add a rework-case test asserting the intended result.

**[important] The seam test uses a stub, not a real multi-line-JSON producer.** The SystemExit(0)/(2) tests use a stub printing one clean JSON object, but `transition_state` (`state.py:131`) prints indented multi-line JSON and returns normally (no SystemExit). **Resolution**: add an integration case driving a real `state` transition end-to-end, asserting the buffered multi-line stdout is re-emitted byte-for-byte and one event is written.

**[important] The chokepoint's normal-return path is undertested.** All four chokepoint tests cover SystemExit or failure; none covers `run_fn` returning an int without raising — the path every hook and the state command take. **Resolution**: add a normal-return case asserting the event is written and the int exit code propagates.

**[important] End-to-end rendering of unavailable/empty rows is not asserted.** The unit tests cover the harvester's `unavailable` marker and the `(no reason recorded)` row, but the report integration test does not assert the *rendered* table shows the literal `unavailable` (not `0`) and a present-but-empty parks row — a formatting regression would slip through. **Resolution**: assert literal cell contents for the missing-transcript stage and the no-parks stage.

**[informational]** The `COMMAND_MAP` count test hard-asserts 18 entries (`test_dispatcher.py:55`); registering `report` makes 19 and breaks it — add to the impacted-tests list. `known_agents` derives its set from installed persona files, which may be absent under pytest (forcing STALE_FALLBACK on every run); confirm the scan root is parameterizable for fixtures, or the non-fallback branch is untestable. The fail-silent fault-injection case is named for the writer, chokepoint, and injector but not the verification hook — add one (unwritable events path, assert exit 2 preserved, no stdout, no raise). The "no mocks" claim is otherwise credible (clock handled by shape-matching, transcripts by real fixtures).

**Coverage genuinely complete** (verified): the capture gate/level resolver branches (AC-01, AC-09, AC-10), retention with baseline locks (AC-14), and the schema drift-check-vs-runtime-discard split (AC-13, correctly two distinct cases).

## Measurability

**[blocking] First-try vs after-rework "rate" has no defined denominator.** The classification keys on park boundaries, not attempt count, so "first-try pass *rate*" is ambiguous: three attempts before a park (fail, fail, pass) could be 1/3 or "first-try phase eventually passed" = 1/1. AC-07 never defines the numerator/denominator, and the single-attempt labeling test would pass with either arithmetic. **Resolution**: state the exact formula for each rate covering the multi-attempt-before-park case; add a fixture with N>1 attempts on one side asserting the specific numeric rate, not just the label.

**[blocking] The kill-rate's documented bias is neither surfaced nor pinned.** The arithmetic is well-defined and recomputable (good), but the design's own limitation — an acknowledged-and-queued true positive stops being re-raised and reads as "killed" — is a systematic bias whose magnitude depends on exactly the population you most want to count, and nothing asserts the bias is stable across compared cycles. AC-05/AC-07 verify the event/row are *present*, never that the rate equals a known value. **Resolution**: state in the spec that the kill rate is a relative trend signal, not an absolute correctness measure; add a unit test feeding a fixed rounds-file and asserting the exact kill-rate value; have the report surface the acknowledged-true-positive caveat.

**[blocking] The token hard-split's cross-cycle invariance — the feature's headline use case — is asserted, not measured.** The before/after comparison's validity rests entirely on the boundary misattribution being "identical across compared cycles," but that error depends on how many turns land within a transition window, which varies by how the work chunked — it is not constant. AC-06 tests only that the split rule executes, not that the resulting error is bounded or stable. **Resolution**: either downgrade the claim (label token-per-stage a coarse indicator not valid for fine cross-cycle deltas) or make it measurable (emit a count of boundary-adjacent turns per stage so a consumer can see how much of a stage's total sits near a boundary).

**[important] "Unavailable vs zero" has no defined rendering for an automated check.** The behavior is precise and unit-tested, but the spec never fixes the literal token the report prints for unavailable, unlike the provenance marker which *is* pinned. **Resolution**: fix the exact rendered string for each of the three cases (unavailable token row, true-zero empty row, `(no reason recorded)` park) so a test can assert them.

**[important] "Empty row vs absent row" has no general rule.** AC-17 says a no-event row is present-and-empty, but the PRD says the verification row is *omitted* when no SDL task completed — a direct tension with no predicate to decide which category a row falls in. **Resolution**: state the rule (present-and-empty when the stage ran but produced no events of that kind; omitted only when the producing step never ran); test both with a fixture.

**[important] AC-20 is the looser of the two cycle criteria and smuggles an unbounded quality.** "A single cycle produces a report whose rows draw on both sources" does not say which rows must be populated; AC-07's row list is verified only against a fixture, not a real cycle. **Resolution**: have AC-20 enumerate the minimum rows a real one-cycle run must populate (reference AC-07 scoped to "stages that ran"). Separately, reword AC-20/IF-D-09's "stripped match" to "matches by structure with the timestamp as a free field," to agree with the test note that asserts marker *shape*, not exact equality.

**[informational]** The ~8ms gated-off path is prototype-measured (good grounding); the PRD's "well under a second" gate budget has no AC or test — optionally add a generous wall-clock upper-bound assertion (e.g. under 100ms on an uninstrumented `tmp_path`). Rework derivation assumes the state engine retains *repeated* stage entries rather than last-write-wins — confirm in the spec (the "error history" reference suggests it does) and add a re-entered-stage fixture test, or rework and after-rework rates are silently uncomputable.

## Testing strategy assessment

The review's assessment of the spec's testing strategy across the three required categories. Detail and the independent test-reviewer verdict follow in "Test Strategy Review."

- **New tests needed** — the spec enumerates new tests per slice with AC traceability, but two acceptance criteria are inadequately covered: the router's write-location guarantee (never the global config dir) has no test asserting *where* the event lands, and the router process's own fail-silent path (an unwritable events path → exit 0, no stdout) is untested. Both are blocking and must be added before the test set is authored.
- **Existing tests impacted** — the spec's claim is factually wrong: it asserts `test_gates_spec.py` and `test_gates_task_reviewer.py` assert the `audit.log_event` calls; verified, neither file references audit logging at all, so there are no assertions to retire and the audit-to-event-writer swap would ship untested. The dispatcher command-count assertion (hard-coded 18) is also an impacted test the spec omits — registering `report` makes 19. Both must be corrected.
- **Test infrastructure changes** — the spec's fixtures (event-stream builder, transcript fixtures, temporary-project fixtures, stdin-payload helper) are appropriate and the "no mocks needed" claim is correct. One gap: `known_agents` derives its set from installed persona files that may be absent under pytest, so the scan root must be parameterizable for a fixture, or the non-fallback branch is untestable.
