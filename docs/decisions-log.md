## 2026-09-07 — Implement an evidence-driven 0.6.0 on an isolated branch

**Context and authority**: The operator asked Astra to create a branch from `develop/0.6.0`, work out the best plan using current research and Claude Code documentation, and implement it autonomously. They also warned that existing AI-written tests may be vacuous. `develop/0.6.0-astra` preserves the earlier notes in commit `e889a0b`. The [plan](0.6.0/plan.md) records the research, its limits, and the replacement design. This is a branch-local implementation under that authorization, not a claim that each change below was individually ratified in an interview.

**Decided**: Supersede the earlier 0.6.0 proposals where they conflict with these implemented choices:

- Use one atomic, checksummed JSON unit record, with derived status and a single writer lock, instead of coordinating YAML verdicts, markers, closure records, and restoration. Keep parent dependencies and file evidence explicit.
- Keep requirements, specs, scope, tasks, and state in git. This deliberately reverses the earlier task-file deletion choice: fresh-checkout rework can revalidate the original work without reconstructing evidence. Runtime locks and telemetry remain untracked.
- Separate direct slash-command expansion from model Skill calls. A live Claude Code 2.1.263 probe confirmed that direct invocation emits `UserPromptExpansion` without `PreToolUse(Skill)`. Both hooks and explicit commands use the same transition engine.
- Use bounded, revision-bound independent review. A second configured reader is optional; suggestions do not force repairs. Three attempts persist across fixes and restarts. Reopening starts a fresh generation; an operator can extend the budget explicitly. Do not reset the budget after each fix.
- Make feature design optional when architecture and shared contracts remain unchanged. Describe observable behavior and shared interfaces precisely; let implementation choose private functions and classes.
- Require declared behavioral checks and locked tests, with a documented preservation path for refactoring. Treat passing test counts as insufficient evidence; exercise realistic failures and selected runtime mutations.
- Use the `.fbk/` protocol end to end. Do not fabricate acceptance records for historical work.
- Report review usage actually returned by headless Claude. Do not claim full per-phase authoring-token accounting. Headless review uses the authenticated Claude Code subscription; no provider SDK or API-credit dependency is introduced.

**Alternatives and rationale**: The earlier multi-file protocol and mandatory dual-reader choreography offered richer bookkeeping at substantial recovery and context cost. Research supports focused interfaces, explicit requirements, and executable feedback, but does not prove those extra mechanisms improve maintainability. Keeping durable evidence and testing the dangerous boundaries is a simpler initial implementation.

**Constrains**: The [workflow guide](../assets/fbk-docs/state-driven-workflow.md) and [architecture overview](architecture-overview.md) describe the implemented contract. Historical artifacts retain their original text. [Validation](0.6.0/validation.md) distinguishes mechanical tests, live host evidence, independent review, and unproven quality claims. Hooks remain cooperative enforcement with documented shell and timeout gaps.

## 2026-09-07 — Select independent single or council review for design and spec

**Authority**: After discussing the council research and phase responsibilities,
the operator agreed to implement a shared, persisted review selection at both
design and spec. They subsequently endorsed having the runtime create headless
reviewers and hand them instructions rather than relying on agent instructions
to spawn acceptance reviewers.

**Decided**: Review mode and design routing are independent. Existing preferences
or explicit project defaults govern; otherwise the lead recommends a plan and
asks the human. Persist each choice and relevant council perspectives. A council
at design does not imply another at spec. Design examines approach and tradeoffs;
spec examines fidelity, observable contracts, integration, and verification.

The runtime starts fresh read-only headless Claude sessions: two or three
independent perspectives, then one evidence-focused challenge and a separate
fresh assessor when candidates exist. Candidate ledgers, not full discussions,
move between stages. Each claim receives a disposition; agreement is not required.
Unresolved blocking findings remain blocking. Required failures never trigger a
silent single-reviewer fallback. One attempt is charged to the existing phase
budget. Mode/membership changes invalidate cached review and old grants while
retaining attempts. Accepted phases require reopen before changing the plan.

**Tradeoffs**: The implementation uses the configured native model for each
perspective; role differences do not prove independent model errors. Sessions
are subprocesses rather than teammates visible in the authoring session. The
initial council has one challenge pass per close attempt; it does not implement
an automatic second debate round. Additional investigation uses an explicit
close attempt within the persisted budget. Consultation remains advisory and
cannot approve its own artifact. Current accepted records remain valid until their dependencies change or they are explicitly reopened.

**Evidence boundary**: This is the operator-approved engineering design, not a
claim that council is empirically superior. [The research note](0.6.0/council-research.md)
records the model-recency and comparison limitations. Runtime and live validation
are recorded separately in [review-selection validation](0.6.0/review-selection-validation.md).

## 2026-09-12 — Treat the reviewer turn ceiling as a safety net, not a budget

**Authority**: The operator decided that hitting the `reviewer_max_turns` cap should no longer pause a phase for human help. A turn count is a proxy for cost, and a cap of 12 punished the source reading and delegated investigation the framework itself asks for.

**Decided**: Raise the default `reviewer_max_turns` to 100 and keep the setting name. The ceiling still applies to readers, council members, challengers, assessors, and delegated investigation workers. Reaching it is an ordinary failed attempt: the round or investigation attempt records the failure with its diagnostics (host output, exit code, reported turns, configured limits) and no exhausted-budget marker, so further attempts run while rounds or attempts remain. The review round limit and the investigation attempt limit are the repetition controls. Time exhaustion is unchanged and still pauses for human help.

**Constrains**: A looping session is still bounded by the ceiling and by the time limit. `extend-review` remains the path after a time pause or an exhausted round limit; it is no longer needed after a turn-ceiling failure.

**Supersedes**: The live-trial remediation choice to preserve a default of 12 and escalate exhausted turn budgets to the human.

## 2026-09-12 — Give the host one flat response schema and state length budgets in the prompt

**Authority**: A live review round burned five host retries and fifteen turns after a summary ran 126 characters over the schema limit. The operator decided both repairs on the Firebreak side, since the host's validator and retry loop are outside Firebreak's control.

**Decided**: The schema passed to `claude -p --json-schema` is one flat object with no top-level union: the review fields, the context inspection record, and the investigation request are sibling properties, and nothing is required at the top level. The host then reports a single clear error per property instead of the merged failures of every union branch. Firebreak enforces the choice after parsing: an object holding only an investigation request is an investigation; an object with no investigation property must be a complete review; a mixed or empty object fails with a message naming the problem. Every native reviewer session prompt states the length budgets the schema enforces, derived from the schema itself, so the prompt and the validator cannot drift.

**Constrains**: Investigation requests keep their nested mode union, which the host accepts below the top level. Documentation describing the structured response shape names the flat object, not an envelope.

**Supersedes**: The `response`/`anyOf` envelope that wrapped the complete review and the investigation request as alternative branches, and prompts that left the length limits unstated.

## 2026-09-12 — Accept a validating review even when a satisfied investigation request rides along

**Authority**: A live council round lost a complete review holding two genuine blockers. The reader had commissioned an investigation, received its evidence, and then returned the finished review together with the already-satisfied request. The runtime rejected the whole object as mixed, the council failed with no single-reviewer fallback, and a phase round was burned. The operator decided the runtime should keep a review that validates on its own.

**Decided**: When a managed reader's response carries both review fields and an investigation request, the runtime validates the review fields with the request removed. If they validate, the review is the final result; the response gains an `ignored_investigation` entry naming the request id and stating that the request was not run, and that entry persists in the round's reader record. If the review fields do not validate, the response fails with the existing mixed-response error, so the failure names the mixing. An investigation-only response and an empty object keep their existing handling. The prompt still says never to combine the two and now states the consequence: the review is taken as final and the request is discarded.

**Constrains**: Tolerance lives in the runtime, not the contract; the instruction text is unchanged in force. A discarded request is never executed, so no investigation budget is spent on it. A mixed response whose review fails only because its inspection declaration misses required paths carries those paths on the mixed error, so the reader takes its ordinary one-shot correction for the missing paths instead of failing outright.

**Supersedes**: The rule in the flat-schema decision above that any mixed object fails.

## 2026-09-12 — Record a refused external check as evidence, not a reader death

**Authority**: A live council round lost two completed peer reviews when one reader asked for an external check (whether `uv run` could reach the network) without an authorization grant. The refusal was correct; the plain error it raised escaped the reader loop, killed the reader with empty diagnostics, and burned the phase review round. The operator ruled that an unanswered investigation question is a caveat in the review, never a fatal error for the reader.

**Decided**: Authorization refusals raise a distinct refusal error. The investigation records a `refused` attempt carrying the reason, with no workspace, no command, and zero seconds, plus an `investigation-refused` event on the round. The managed reader receives the refusal in its evidence prompt (question, reason, and an instruction to proceed without that evidence or report the question as unresolved) and finishes its review; the review's conclusion may cite the refused attempt, so the round still closes cleanly. No protocol correction is spent. The refused attempt counts toward the attempt limit, so repeated requests reach the ordinary attempt escalation instead of looping. Any other error escaping investigation dispatch is recorded on the round with the round identifier and a summary of the reader's prior responses before it propagates.

**Constrains**: An unauthorized check still never launches. The security boundary is unchanged: the host sandbox, not this record-keeping, restricts what a command can reach. Human disposition remains the path once the attempt limit is reached.

**Supersedes**: Treating an unauthorized external check as a plain workflow error that ends the reader session.

## 2026-09-12 — Count a supporting source as an inspected source

**Authority**: A live council round discarded a phase review with three completed readers. The challenge-stage reader listed twenty-three of twenty-four required paths in `inspected_files` and the last one, a decision record, only in `supporting_files`. The validator called that a missing required path, the reader had already spent its one protocol correction, and the round failed. The operator ruled that a file the reader declares as a supporting source it relied on is, by definition, a file it read.

**Decided**: The inspection declaration is the union of `inspected_files` and `supporting_files`. Required paths are checked against that union, and so is the rule that every declared path lies inside the controlled snapshot. The correction message for a genuinely missing path tells the reader that a required path may appear in either list. The two lists stay separate in the stored record, because supporting-file freshness tracking reads `supporting_files` on its own.

**Constrains**: Shape, bounds, status, and missing-context checks are unchanged. The prompt still asks readers to reserve `supporting_files` for governing authority documents and shared contracts; that is guidance about classification, not a validation rule.

**Supersedes**: The rule that every supporting file must also be listed in `inspected_files`.

## 2026-09-12 — Show reviewers the exact required file list the validator enforces

**Authority**: A live council round lost a completed round with three finished readers because the challenge reader's declaration missed fourteen of twenty-four required paths, and its corrected attempt failed the same check again. The prompt never labeled which paths were required, and the challenge stage said nothing about the declaration. The operator decided that the deterministic check may enforce only what the prompt states.

## 2026-09-12 — Give a reader one correction for a declared path outside the snapshot

**Authority**: A reviewer that spells a declared path differently from the snapshot listing (a directory, a wildcard, a `./` prefix, an absolute path, or a file it never received) failed the declaration check with a plain "outside the controlled snapshot" error carrying no typed attribute. The managed reader loop re-prompts only on typed declaration errors, so the reader died on the spot, and in a council the whole round was discarded. The operator ruled that this is the same one-shot-correctable declaration mistake as a missing required path.

**Decided**: The declaration validator raises a typed error for unknown paths, carrying `inspection_unknown_paths` and a message that lists the offending entries sorted (the first twenty-five, with a count of the rest), states that each entry must be a file path spelled exactly as in `required_files` or the snapshot listing with no directories, wildcards, `./` prefixes, or absolute paths, and tells the reader to correct the declaration and resubmit. The review session copies that attribute onto the wrapped error and into diagnostics as `unknown_inspection_paths`, for a plain review and for a mixed response whose review branch fails only on this check. The managed reader loop spends its one protocol correction on either declaration error, and the correction record carries `unknown_inspection_paths` beside the existing `missing_inspection_paths`.

**Constrains**: Missing required paths are checked first and still win when both problems exist. The reader still gets exactly one correction per round across every declaration error, so a second unknown-path failure stops it with the exhausted-correction indicator. The contradiction-repair verifier runs through the same review session and gains the diagnostics without a loop of its own.

**Supersedes**: Treating a declared path outside the snapshot as a plain, non-correctable workflow error.

## 2026-09-12 — State every remaining validator rule in the native reviewer prompt

**Authority**: An audit of the native reviewer session found deterministic checks the prompt never stated: the three top-level properties a managed review must carry, the three authorization grant rules and the refusal that follows a missing grant, the coupling of investigation mode to `argv`, the per-investigation attempt and time budgets, and the context record's list caps. The operator's standing rule applies: every deterministic check on model output is stated in the prompt, generated from the data the validator reads wherever possible.

**Decided**: The managed instruction block now names the complete-review properties from the schema's required keys plus `context`, so a contributor session names `result, context` and a review session names `summary, findings, context`. It states that a valid grant copies its quote verbatim from the cited file, matches the external target exactly, and covers every external effect, and that a request declaring `external` without such a grant is refused, recorded, runs nothing, and spends one attempt. The length-budget sentence is rendered from the wire schema rather than the base schema, so every session also states the context record's caps.

**Supersedes**: Prompts that said only "budgets do not renew" and left the review shape, grant rules, mode coupling, and context caps to be discovered through validator errors.

## 2026-09-12 — An honest incomplete declaration is a verdict; a refuted duplicate reference is noise

**Authority**: The harness punished truthful readers worse than lying ones in two places. A reader that reported `context.status: incomplete` with the missing evidence named, exactly as the prompt invited, was rejected as invalid review JSON: a harness failure with diagnostics that killed the reader and, in a council, discarded the whole attempt. Separately, the canonical adjudication validator rejected any refuted assessment that also carried `duplicate_of`, a rule the adjudication prompt never stated, and the failure discarded a complete council round. The operator ruled that a deterministic check may reject a malformed claim, never an honest one.

**Decided**: The context validator accepts both statuses under one shape rule: `complete` requires an empty `missing_context`, `incomplete` requires it to name each missing item, and only a contradiction is a malformed declaration. Required-path and unknown-path checks still run for both statuses. Downstream, any incomplete reader (a single reader, a council member, or a challenge or adjudication pass) makes the round result record `incomplete_context` entries of member, stage, and missing items, sets the round error to "Review incomplete; missing context: ..." naming those items, and leaves the phase unaccepted. The round is consumed like a substantive rejection: no `failure_diagnostics`, no `budget_exhausted` marker, no human-review pause, and the reader's summary and findings stay in the round record for the author. A council stops before challenge and adjudication when an independent reader is incomplete, retaining every finished reader; a retry reuses finished peers and runs the incomplete reader again. The prompt states the consequence and the shape rule in the context-completeness block. A standalone contributor that reports incomplete is recorded as failed with that plain reason rather than marked complete. For adjudication, a refuted assessment's `duplicate_of` is dropped before the duplicate rules run, so grouping never sees it, and the adjudication prompt says so; the direct-representative, no-self-reference, no-chain, same-disposition, and null-finding rules are unchanged.

**Constrains**: An incomplete round still counts against the phase round limit, so repeated incomplete verdicts reach the same human escalation as repeated rejections. The contradiction-repair verifier shares the validator and now receives an incomplete context record instead of an error; the repair module maps that declaration to an `insufficient_context` verdict naming the missing items, so an incomplete verifier can never apply a repair.

**Supersedes**: Treating `context.status: incomplete` as invalid review JSON, and rejecting a refuted assessment for carrying a duplicate reference.

## 2026-09-12 — Exhaustion is a caveat; a verifier's honest negative is a verdict

**Authority**: Magnitude limits are safety nets. Exhausting one means "this question could not be answered within budget", which is a caveat in the review, never a reason to kill the reader. Two verifiers accepted a negative answer per their prompt and then treated it as a failure. The operator ruled that a verifier's honest negative is its verdict, not a protocol failure.

**Decided**: When a managed investigation exhausts its per-question attempt or time limit, the entry keeps its `human_review` record and the escalation event, but the reader continues: the next continuation carries the question as unresolved evidence with an `exhausted` note (the limit reached, the attempts made, and the instruction to proceed without it or report it unresolved). The reader's conclusion citing the attempts resolves the entry, exactly as a refused attempt does, so the review lands with no `budget_exhausted` diagnostic. Asking for the exhausted question again returns the same evidence for free; a third request stops the reader with a diagnostic naming the question. A per-question exhaustion no longer blocks starting other questions or re-activating the round for a later council stage. The round clock (`review-time`) stays fatal and pauses for a human. The managed prompt now says that when either limit is exhausted the question is returned as unresolved evidence and the reader finishes without it. The contradiction-repair verifier's `rejected` and `insufficient_context` verdicts leave the file untouched and raise "Repair not applied: verifier returned <verdict>: <evidence>" with no host or validation diagnostics; its prompt states that consequence. The remediation verifier's `rejected` report is accepted structurally (assessment, rejected_behavior, limitations and an attributed behavior-evidence quote are required; red/green exit codes, defective source and sibling accounting are verified-only), recorded as the remediation's verdict with the `rejected_behavior` text and an `independent-remediation-rejected` event, and reported as "not accepted: independent verifier returned rejected: <rejected_behavior>".

**Constrains**: Round-level escalations (the review clock and interrupted assignments) still require human disposition before completion and before another question starts. Malformed verifier reports still raise as invalid. A rejected remediation stays a pending obligation; the round cannot complete until a fix is verified.

**Supersedes**: Treating a per-question attempt or time exhaustion as a fatal `budget_exhausted: investigation-<limit>` pause, and treating a verifier's rejected or insufficient_context answer as "verification did not establish fidelity" or an invalid report.

## 2026-09-12 — Scan artifacts for invisible characters before a round, and ask readers for every blocker at once

**Authority**: A spec about line-boundary characters carried four raw invisible characters (a vertical tab where the JSON escape should have been shown, among others) through three council review rounds unnoticed; a one-command byte scan finds them instantly. Separately, three consecutive rounds each returned exactly one blocker, and the third round's blocker already existed in round one, so a three-round budget serialized findings one round could have reported together. The operator's rule for deterministic checks applies: they may test harness-supplied data and artifact structure at any project scale, never project-specific content judgments. A byte-level character scan qualifies; the reviewer physically cannot see what it finds.

**Decided**: `phase-close` runs an artifact hygiene scan (`fbk/workflow/artifact_hygiene.py`) before any round is appended or reviewer launched, over only the unit's own subject files under `.fbk/<unit>/` for that phase (never code, tests, or context sources). It reports C0 controls other than tab, newline, and carriage return; DEL; U+0085, U+2028, U+2029; and U+FFFD from undecodable bytes, each as `path:line:column U+XXXX NAME` with 1-based character positions. Binary-looking files (a NUL in the first 8 KiB) and files over 4 MiB are recorded as skipped, not clean; findings are capped at fifty with the total retained. A hit raises a `WorkflowError` listing every finding and telling the author to write the character as an escape or remove it, then close again; it consumes no review round. The scan report (`clean`, `findings`, or `skipped`, with scanned and skipped paths) is recorded on the `close-attempt` event. The base review prompt now says: "Report every blocker you can demonstrate in this pass, across the whole artifact and not only the recently changed region, because each round is budgeted and a blocker left for the next round costs a round."

**Constrains**: No new phase state and no CLI command; a standalone helper (`require_clean`) exists for later wiring. The scan judges bytes only; it never inspects artifact meaning. A skipped file is disclosed, not treated as a pass. The prompt change adds one sentence and alters no other instruction.

**Supersedes**: Relying on reviewers to notice invisible characters, and prompts that left the number of blockers per pass to reviewer discretion.

## 2026-09-12 — A post-exhaustion suspend note leads the next action, and the retrospective reaches a long history in one step

**Authority**: A live unit whose spec phase ran ten review rounds showed two handoff failures. The agent suspended after exhaustion with a note saying the fix was written and only authorization for another round was needed; the resuming agent followed the fixed "present failed stages" next-action, spent four tool calls re-presenting a failure the operator had already seen, and the authorization arrived unprompted. Separately, the history pointer offered by status and continuation (`retrospective <unit> --section phases --index N`) returned an omission naming only the entry's top-level children, and the events index reported 236 entries, listed the first 33, and offered no way to continue, so reaching the latest events took 21 single-index calls.

**Decided**: The exhausted-budget next action reads the unit's events. When the most recent suspend note postdates the phase's `human-review-required` event, status, continuation, and the Stop hook lead with that note (quoted, bounded to 400 characters), name the human's authorization for another review round as the open item, and give the `extend-review <phase> <unit> --rounds 1 --reason` command. Without such a note, or when the note predates the exhaustion, the present-the-failure text stands. The `human_review` block carries the note as `suspend_note` and its history pointers now reach the rounds directly (`--pointer /value/rounds`, `latest_round` at `/value/rounds/-1`). Section order stays oldest-first and is stated on single-section pages.

**Constrains**: The close-time escalation raised inside the phase-close transaction keeps the fixed text, since no post-exhaustion note can exist at that moment. Entries keep their one-based index in the full section regardless of paging. The all-sections summary stays terse and carries paging detail only through `next` hints, so a 3000-character bound still yields a usable envelope.

**Supersedes**: A fixed exhausted-budget next action that ignored the unit's suspend note, and a retrospective index with no paging and no phase-specific pointer hints.

## 2026-10-22 — The test checkpoint reviews against a saved baseline and the complete check output

**Authority**: Decisions 3, 4, and 5 of the test-stage amendment (`docs/0.6.0/test-stage-amendment-plan.md`): the reviewer must see which tests the test tasks changed, every production change they made, and the full output that shows each test failing for the right reason. ## 2026-10-22 — Tests kept at the end of a source file are locked as a test region
